# Dify Workflow Contract

The desktop client sends only three workflow inputs:

| Variable | Dify control | Purpose |
|---|---|---|
| `task_type` | Select or text input | `overview`, `analysis`, or `repair` |
| `context` | Paragraph | Dataset metadata generated by the client |
| `query` | Paragraph | The user's original request, unchanged |

Remove the old `system` input. Set `query` and `context` to the largest practical
limits allowed by the company deployment. The client reads the published limits
from Dify's `/parameters` endpoint and rejects oversized requests before running
the workflow.

If `task_type` is configured as a Select control, add all three options:
`overview`, `analysis`, and `repair`.

## Workflow layout

```text
Start
  -> IF task_type == "overview"
       -> Overview LLM
       -> Overview End
     ELIF task_type == "repair"
       -> Code Repair LLM
       -> Repair End
     ELSE (analysis)
       -> Requirement Structuring LLM
       -> Code Generation LLM
       -> Analysis End
```

Use an exact equality condition on `task_type`; do not route by searching prompt
text.

## Overview LLM

Enable structured output and use this JSON schema:

```json
{
  "type": "object",
  "properties": {
    "dataset_kind": {"type": "string"},
    "topic": {"type": "string"},
    "summary": {"type": "string"},
    "rows": {"type": "integer"},
    "columns": {"type": "integer"},
    "sheet_count": {"type": "integer"},
    "suggestions": {
      "type": "array",
      "items": {"type": "string"},
      "minItems": 4,
      "maxItems": 4
    }
  },
  "required": [
    "dataset_kind",
    "topic",
    "summary",
    "rows",
    "columns",
    "sheet_count",
    "suggestions"
  ]
}
```

System prompt:

```text
You are a senior data analyst. Use only the supplied dataset metadata.
Return a concise overview in Simplified Chinese and do not invent facts.
Suggestions must be concrete questions supported by available columns.
Each suggestion must be short enough to use directly as an analysis request.
```

Pass `context` as the dataset metadata. The Overview End node must expose the
structured object as `text` (JSON string) or expose the LLM text output as
`text`.

## Requirement Structuring LLM

Enable structured output:

```json
{
  "type": "object",
  "properties": {
    "task_summary": {"type": "string"},
    "requirements": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "id": {"type": "string"},
          "objective": {"type": "string"},
          "required_columns": {
            "type": "array",
            "items": {"type": "string"}
          },
          "output_type": {
            "type": "string",
            "enum": ["metric", "table", "chart", "insight"]
          }
        },
        "required": ["id", "objective", "required_columns", "output_type"]
      }
    },
    "warnings": {
      "type": "array",
      "items": {"type": "string"}
    }
  },
  "required": ["task_summary", "requirements", "warnings"]
}
```

System prompt:

```text
Break the user's complete request into independently checkable analysis
requirements. Preserve every requirement and its order. Use dataset metadata to
identify required columns. Report missing or ambiguous columns in warnings.
Do not generate Python code.
```

Inputs:

- Dataset metadata: `context`
- Original request: `query`

## Code Generation LLM

Inputs:

- Dataset metadata: `context`
- Original request: `query`
- Structured plan: Requirement Structuring LLM output

System prompt:

```text
You are a Python data-analysis expert.

Data is already loaded in the `dfs` dictionary:
df = dfs["file name"]["sheet name"]

Never read files with read_excel/read_csv and never access the network,
filesystem, processes, environment, sockets, or unsafe Python internals.

Implement every requirement ID from the structured analysis plan. A
pre-initialized result collector named `result` is available:

result.set_summary(text)
result.add_metric(label, value, unit="", detail="")
result.add_table(title, dataframe)
result.add_chart(title, matplotlib_figure, caption="")
result.add_insight(title, detail)
result.add_warning(title, detail)

Use result.set_summary for the executive conclusion. Add useful metrics,
tables, charts, findings, and data-quality warnings when supported by the
request. Tables are automatically bounded by the client. Matplotlib figures are
also captured automatically, but explicit result.add_chart titles are better.
Print only useful audit details.

Return pure executable Python code without markdown fences or explanation.
```

## Analysis End

Expose exactly:

- `code`: Code Generation LLM text output
- `analysis_plan`: Requirement Structuring LLM structured output

The client remains backward compatible when `analysis_plan` is absent, but the
plan is required for complete multi-requirement traceability.

## Code Repair LLM

The client uses this branch only after generated or user-edited code fails
during local execution. No new workflow input is required:

- `task_type`: `repair`
- `context`: dataset metadata plus `failed_code`, `runtime_error`,
  `analysis_plan`, repair attempt number, and the result SDK contract
- `query`: the unchanged original user request

System prompt:

```text
You are a Python data-analysis code repair expert.

The context contains dataset metadata, the complete failed Python code, its
local runtime traceback, the original analysis plan, and the supported result
collector API.

Diagnose the actual runtime failure and return a complete corrected replacement
script. Preserve every requirement in the original request and analysis plan.
Do not return a patch, explanation, markdown fence, or partial snippet.

Data is already loaded in `dfs`. Never read external files or access the
network, filesystem, processes, environment, sockets, or unsafe Python
internals.
```

The Repair End node must expose:

- `code`: Code Repair LLM text output

The client executes the replacement locally and may call this branch again,
up to the configured `MAX_CODE_RETRIES` limit. Dify's ordinary node retry is
still useful for provider/network failures, but it does not replace this repair
branch because the runtime error occurs on the desktop client.
